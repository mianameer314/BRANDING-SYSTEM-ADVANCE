# 🪝 Webhooks API

The Webhooks API provides endpoints to manage outbound HTTP notifications triggered by internal system events (e.g., content publishing). This allows external services, AI automation pipelines, or no-code platforms (like Zapier) to react to state changes in the CMS in real time.

## 📌 Base URL
`/api/v1/webhooks`

## 🔒 Authentication
All Webhook endpoints require the user to be authenticated and have the `create` or `publish` (Admin/Super Admin) permission.

- **Header**: `Authorization: Bearer <token>`

---

## 🚀 Endpoints

### 1. Register a Webhook
Registers a new URL to receive POST requests for specific events and content types.

- **URL**: `/`
- **Method**: `POST`
- **Body** (JSON):
  ```json
  {
    "url": "https://your-server.com/webhook",
    "event": "content.published",
    "content_types": ["blog", "news", "project"],
    "description": "Trigger AI translation pipeline"
  }
  ```
  *(Note: Use `["*"]` in `content_types` to subscribe to all content types.)*

- **Success Response** (`201 Created`):
  ```json
  {
    "id": 1,
    "url": "https://your-server.com/webhook",
    "event": "content.published",
    "content_types": ["blog", "news", "project"],
    "description": "Trigger AI translation pipeline",
    "is_active": true,
    "created_at": "2026-07-24T12:00:00Z"
  }
  ```
  *(The secure HMAC `secret` is auto-generated by the system and only used internally for signing payload headers.)*

---

### 2. List Webhooks
Retrieve a paginated list of all registered webhooks.

- **URL**: `/`
- **Method**: `GET`
- **Query Parameters**:
  - `page` (optional): Page number (default: `1`)
  - `per_page` (optional): Items per page (default: `20`)
  - `is_active` (optional): Filter by active status (`true` or `false`)

- **Success Response** (`200 OK`):
  ```json
  {
    "total": 1,
    "page": 1,
    "per_page": 20,
    "items": [
      {
        "id": 1,
        "url": "https://your-server.com/webhook",
        ...
      }
    ]
  }
  ```

---

### 3. Get Webhook Details
Retrieve details of a specific webhook by ID.

- **URL**: `/{webhook_id}`
- **Method**: `GET`
- **Success Response** (`200 OK`): Returns the `Webhook` JSON object.

---

### 4. Update a Webhook
Modify an existing webhook's properties (e.g., deactivate it or change the URL).

- **URL**: `/{webhook_id}`
- **Method**: `PUT`
- **Body** (JSON, all fields optional):
  ```json
  {
    "url": "https://new-url.com",
    "is_active": false
  }
  ```
- **Success Response** (`200 OK`): Returns the updated `Webhook` JSON object.

---

### 5. Delete a Webhook
Permanently delete a webhook registration.

- **URL**: `/{webhook_id}`
- **Method**: `DELETE`
- **Success Response** (`204 No Content`)

---

### 6. View Webhook Delivery Logs
Retrieve paginated historical delivery logs for a specific webhook, useful for debugging failed delivery attempts.

- **URL**: `/{webhook_id}/logs`
- **Method**: `GET`
- **Query Parameters**:
  - `page` (optional): Page number (default: `1`)
  - `per_page` (optional): Items per page (default: `20`)

- **Success Response** (`200 OK`):
  ```json
  {
    "total": 5,
    "page": 1,
    "per_page": 20,
    "items": [
      {
        "id": 105,
        "webhook_id": 1,
        "event": "content.published",
        "content_type": "blog",
        "content_id": 42,
        "request_url": "https://your-server.com/webhook",
        "response_status": 200,
        "success": true,
        "error_message": null,
        "delivered_at": "2026-07-24T12:05:00Z"
      }
    ]
  }
  ```

---

### 7. Send Test Ping
Manually dispatch a dummy event to verify connectivity and signature validation.

- **URL**: `/{webhook_id}/test`
- **Method**: `POST`
- **Success Response** (`200 OK`):
  ```json
  {
    "success": true,
    "message": "Test event dispatched. Check logs for result."
  }
  ```

---

## 🔐 Webhook Payload & Verification

When an event fires, the registered URL will receive a `POST` request with a JSON body:

```json
{
  "version": "1.0",
  "event": "content.published",
  "content_type": "blog",
  "content_id": 15,
  "timestamp": "2026-07-24T12:10:00+00:00",
  "data": { ... full content object ... }
}
```

### Headers & Security
If `WEBHOOK_SIGNING_ENABLED=True` is set in the environment, requests will include an `X-Webhook-Signature` header computed using HMAC-SHA256 of the payload body against the webhook's secret.

```http
Content-Type: application/json
X-Webhook-Event: content.published
User-Agent: O2Geeks-Webhook/1.0
X-Webhook-Signature: sha256=a1b2c3d4e5f6...
```
